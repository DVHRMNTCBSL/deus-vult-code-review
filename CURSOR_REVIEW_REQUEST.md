# Pedido de revisao tecnica

Objetivo: revisar este recorte publico do Deus Vult como codigo, nao como promessa.

Leia primeiro:

- `README.md`
- `MANIFEST_DADOS.csv`
- `frontend-vitrine/open-source/index.html`
- `python/deus_vult_python/core.py`
- `tests/test_deus_vult_python.py`
- `calculadora-web/index.html`
- `calculadora-android/app/src/main/java/com/deusvult/calculadoraone/MainActivity.java`

O que revisar:

- bugs reais, risco de privacidade, excesso de abstracao e falta de teste;
- se o README permite entender o projeto sem contexto privado;
- se a vitrine e o source deixam claro o que e codigo, tese, hipotese e metafora;
- se a parte Python passa nos testes locais e representa bem a ideia;
- se a parte frontend e Android estao simples o bastante para evoluir.

Limites:

- nao solicitar, publicar ou inferir dados pessoais, documentos, conversas privadas ou contatos;
- nao pedir credenciais, chaves, arquivos locais privados ou historico completo do vault;
- se algo parecer sensivel, registrar como risco e sugerir patch menor.

Formato ideal de resposta:

1. Achados por severidade, com arquivo e linha quando houver.
2. Testes que rodou ou que faltaram.
3. Patch pequeno sugerido.
4. Perguntas objetivas, sem depender de dados privados.

Regra DV: vontade vira forma, forma vira metodo, metodo vira obra auditavel.
