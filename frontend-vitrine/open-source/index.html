Âncora primordial

Linguagem Estrutural Deus Vult

Não é uma linguagem de programação. É um protocolo de organização: gavetas, teses objetivas e evidência rastreável. A metáfora central é o gaveteiro — cada ideia sabe onde mora antes de virar código.

Gavetas base

Axiomas operacionais

  1. Estrutura antes de estilo — toda frase sabe em qual gaveta está.
  2. Tese antes de expansão — toda ramificação nasce de uma tese curta.
  3. Evidência antes de conclusão — prova, hipótese, inferência ou metáfora declarados.
  4. Limite antes de execução — escopo, autorização e registro em ações sensíveis.
  5. Extensibilidade sem caos — gavetas novas declaram nome, função e relação com o núcleo.
  6. Inteligibilidade antes de expansão — ponte para quem não conhece todo o histórico.
  7. Prática antes de abstração final — teoria entregue vira ação, critério de pronto ou decisão.

Classificação obrigatória

Todo claim no ecossistema DV passa por um destes tipos antes de virar código ou documento:

  • PROVA arquivo, hash, fonte verificável
  • TESE proposição estruturante aberta a debate
  • HIPÓTESE inferência plausível que precisa de teste
  • METÁFORA imagem orientadora, não fato técnico
  • DECISÃO escolha operacional do controlador

Fonte canônica: DEUS_VULT_LINGUAGEM_ESTRUTURAL.yaml · versão 0.1

Equilíbrio dinâmico

Homeostase: entendimento ↔ teoria ↔ prática

Nenhuma linguagem de programação governa as outras. O que governa é o invariante vivo: clareza, dignidade, verdade operacional, limite e serviço — regulados em ciclo contínuo entre três frentes iguais.

Entendimento

Ponte para quem não viveu todo o histórico. Resumo em uma frase, o que serve, o que não é, risco principal.

  • Intra-interação: DV conversa consigo antes de falar para fora
  • Desintegração: quebra em peças nomeadas e traduzíveis
  • Integração: forma externa que alguém consegue usar

Ref: DEUS_VULT_INTELIGIBILIDADE_INTERSUBJETIVA.yaml

Teoria

Estrutura dimensional, YAML canônico, retroalimentação adversarial, gates de vida. Teoria sem prática é loop — teoria com prova vira patch, teste ou backlog.

  • Snapshot finito com hash e escopo delimitado
  • Steelman: reconstruir a crítica mais forte antes de responder
  • Classificação PROVA · TESE · HIPÓTESE · METÁFORA · DECISÃO

Ref: AGENTS.md · DEUS_VULT_PROGRAMA_RETROALIMENTACAO.yaml

Prática

Micro-ação verificável em qualquer linguagem. Calculadora, gateway, vitrine, scripts de loop, APK offline — cada caminho executa o mesmo protocolo de forma diferente.

  • Próxima ação menor que aumenta vida e clareza hoje
  • Critério de pronto explícito antes de fechar tarefa
  • Evidência registrada: teste, audit ou hash

Ref: DEUS_VULT_ESSENCIA_HOMEOSTASE_VIDA.yaml

Obra coletora · honeypot

Coletora unilateral — aberta, não bilateral

O open source Deus Vult é uma obra coletora: atrai contribuições, registra uso legítimo no território DV e retroalimenta o protocolo. Não é troca bilateral — você entra, usa, contribui se quiser; o fluxo é unidirecional e aberto, não negociação fechada entre duas partes.

  1. 1
    Obra

    Ferramenta útil publicada — calculadora, vitrine, bilhete, gateway.

  2. 2
    Uso legítimo

    Triagem, simulação, feedback limpo dentro do domínio DV.

  3. 3
    Track record

    Eventos locais ou fila até sync — só no território DV, sem CPF/senha/token.

  4. 4
    Main server

    Controlador aplica DV: audit, retro, patch · teste · backlog.

O que não é

  • Não é marketplace de troca simétrica
  • Não é reciprocidade humana simulada por IA
  • Não é acordo fechado antes de usar

Metáfora

Arapuca coletora — obra útil; quem pisa deixa o sapato (track record). Fora do domínio DV não há rastreio.

Ref: DEUS_VULT_OBRAS_COLETORAS.yaml

Política open source

Roadmap do gateway: apenas código aberto e/ou pesos totalmente abertos. APIs closed-weight (OpenAI, Gemini, Anthropic consumer) ficam fora de escopo até existir pipeline aberto verificável.

Porta de entrada

Como entrar e contribuir

Quinze minutos para começar. Uma hora para a primeira contribuição real. O protocolo exige classificação e evidência — não promessa vaga.

01

Ler o mapa

Abra CURSOR_MASTER_INDEX_DEUS_VULT.yaml e DEUS_VULT_LINGUAGEM_ESTRUTURAL.yaml. Classifique o que você vê antes de editar.

02

Escolher seu caminho

Node, Python, HTML ou Android — entre pela pasta que fala sua linguagem. O gaveteiro é o mesmo.

03

Micro-ação com prova

Um patch pequeno, um teste, um YAML com hash. Saída de loop: patch · teste · backlog · descarte justificado.

04

Contribuir unilateralmente

Pull request, issue ou fork — fluxo aberto. Sem negociação prévia obrigatória. Respeite gates: sem segredos, sem dados sensíveis.
